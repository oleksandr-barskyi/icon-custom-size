# Icon: customSize

Тестове завдання: доробити `Icon.tsx` (React + tailwind-variants + lucide-react) так, щоб числовий `customSize` коректно перевизначав розмір, заданий варіантом `size`.

Історія комітів: перший коміт містить оригінальний файл із завдання, другий містить рішення. Зміни зручно дивитись у diff другого коміту.

## Рішення

- `customSize` передається в нативний проп Lucide `size`: він виставляє `width` і `height` самого SVG. Одне джерело розміру, без інлайн-стилів.
- Коли `customSize` задано, клас `size-*` не додається взагалі. Інакше CSS-клас переміг би атрибути SVG, і розмір лишився б з варіанта.
- Значення за замовчуванням `size = 'sm'` перенесено з `defaultVariants` у пропси компонента. У tailwind-variants `size: undefined` означає «взяти default», тож із default у `tv` клас `size-4` повертався б навіть при `customSize`. Передати `null` не дають типи `VariantProps`, а приводити тип не хотів.

## Чому не інше

- **Інлайн `style={{ width, height }}`**: два джерела розміру (атрибути SVG 24 і стиль), плюс конфлікт із класом `size-*`.
- **Довільний клас `size-[40px]` з числа**: Tailwind генерує класи під час збірки, рядок, складений у рантаймі, у CSS не потрапить.
- **Варіант `size: { custom: '' }`**: у публічний тип пропа потрапляє значення, яке без `customSize` нічого не означає.

## Компроміс

`iconVariants()` без `size` тепер не додає клас розміру. Компонент поводиться як раніше (default `sm`), а зовнішній код, що викликає `iconVariants` напряму, має передавати `size` явно.

## Перевірка

```bash
npm install
npm run typecheck   # tsc --strict, без помилок
npm run check       # рендер через react-dom/server, виводить атрибути SVG і класи
```

| Пропси | SVG width/height | Клас розміру |
|---|---|---|
| без пропсів | 24 (атрибут) | `size-4` |
| `size="lg"` | 24 (атрибут) | `size-6` |
| `customSize={40}` | 40 | немає |
| `size="lg" customSize={40}` | 40 | немає |
| `customSize={40} color="error" className="ml-2"` | 40 | немає, `text-red-600 ml-2` збережені |
